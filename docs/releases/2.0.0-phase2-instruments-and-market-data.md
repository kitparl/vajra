# Phase 2 slice 1: instrument master and market data from Delta testnet

## Summary
`brahma` (core-service) now loads Delta India **testnet** products, keeps live quotes for BTCUSD and ETHUSD, stores 1-minute candles with automatic gap backfill, and serves instruments and candles over REST. First slice of Phase 2 (feature → major).

## Changes
- Delta public REST client, testnet base URL only (no production URL in code). On HTTP 429 all Delta calls pause for `X-RATE-LIMIT-RESET` (60 s if missing).
- `ExchangeConnector` interface with `DeltaConnector`; common model `Instrument`, `Quote`, `Candle`, `Venue`.
- Instrument master: all live perpetuals stored; trading enabled only for `vajra.marketdata.symbols` (default `BTCUSD,ETHUSD`). Refresh every 6 h, retried every minute until the first success.
- Quotes polled every 2 s into an in-memory cache; older than 10 s counts as stale. A malformed ticker is skipped.
- 1-minute candles: first run backfills 7 days; each run continues from the last stored candle, so downtime gaps are filled.
- One scheduler thread per job, so a long backfill never blocks the quote poller.
- REST: `GET /api/v1/instruments`, `GET /api/v1/candles?symbol=&from=&to=` (ISO-8601, `[from, to)`, max 7 days; 400/404 with `{"error": ...}`). Decimals returned as plain strings.
- New property `vajra.scheduling.enabled` (default `true`); integration tests set it to `false` so CI never calls Delta.
- Docs: knowledge `0022-market-data-by-rest-polling.md`, Hinglish note `09-exchange-connector/02-instruments-aur-candles.md`.

## DB migrations
Schema `core` (Flyway, `brahma`):
- `V2__instrument.sql`: table `instrument` (unique `venue, symbol`).
- `V3__candle_1m.sql`: table `candle_1m` (primary key `instrument_id, open_time`, FK to `instrument`).

## Contract changes
None (no Protobuf or Kafka changes). New REST endpoints listed above.
