# Role names in code, Sanskrit only in folder names

## Summary
The Sanskrit service names (`brahma`, `maryada`, `dvara`, `manthan`, `shankha`) are now used only as folder names under `services/`. Code, config, build files, compose services, hostnames, logs and docs use the role names, so you can tell which service is which from a stack trace or container name. Behaviour does not change, but deploy names do, so this is a minor bump.

## Changes
- **Java packages and classes:**
  - `com.vajra.brahma` → `com.vajra.coreservice`
  - `com.vajra.maryada` → `com.vajra.riskservice`
  - `com.vajra.dvara` → `com.vajra.gatewaybff`
  - `BrahmaApplication` → `CoreServiceApplication`, `MaryadaApplication` → `RiskServiceApplication`, `DvaraApplication` → `GatewayBffApplication`
  - `MaryadaRiskGate` → `RiskServiceGate`; the matching tests are renamed too.
- **Maven `artifactId` and `spring.application.name`:** `core-service`, `risk-service`, `gateway-bff`. Jars are now named `core-service-*.jar` and so on.
- **Python:**
  - Packages `manthan` → `research_service` and `shankha` → `signal_service`.
  - uv names are now `research-service` and `signal-service`.
  - FastAPI titles are `ResearchService` and `SignalService`.
  - `uv.lock` was regenerated.
- **Compose:**
  - Services renamed to `core-service`, `risk-service`, `gateway-bff`, `signal-service` and `research-service`.
  - Hostnames: `RISK_BASE_URL=http://risk-service:8082` and `CORE_BASE_URL=http://core-service:8081`.
  - `build.args.SERVICE` is still the folder name.
- **Dockerfiles:**
  - `java.Dockerfile` copies `target/*.jar`, so it does not depend on the artifact name.
  - `python.Dockerfile` takes `SERVICE` (folder), `PACKAGE` (uv name) and `MODULE` (import name).
- **Scripts:** `check-memory.sh` expects the new container names, and its name column is wider.
- **Contracts tests:** the producer example is now `core-service`. The `.proto` files are unchanged.
- **Docs:**
  - New knowledge doc `0025-role-names-in-code.md`. The naming part of `0013` is marked `Superseded by: 0025`.
  - Service READMEs now use the title format `# core-service (folder: brahma)`.
  - Updated common, infra and root docs, the Hinglish notes and a CLAUDE.md line.

## DB migrations
None. Schemas and roles (`core`, `core_svc`, …) are unchanged. Flyway migration files were deliberately not edited, because changing them changes their checksums.

## Contract changes
None. No Protobuf or REST API changes. Audit events were already published as `core-service`.

## Breaking changes
- **Compose service names and hostnames changed.**
  - Scripts or commands that name a service need the new name, for example `compose.sh up -d core-service`.
  - On first deploy, run `scripts/compose.sh up -d --build --remove-orphans` so the old containers (`vajra-brahma-1`, …) are removed. This removes containers only; the `pgdata` and `kafkadata` volumes stay. Never use `down -v`.
- **Build args:** building a Python image by hand now needs `--build-arg PACKAGE=... --build-arg MODULE=...`.
