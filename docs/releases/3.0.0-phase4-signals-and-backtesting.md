# Phase 4: signals and backtesting

## Summary
This release adds the first real strategy, an SMA crossover. One shared piece of Python code makes the decision both live (signal-service, paper or testnet) and in a new backtester (research-service, which runs on the laptop only). That means a backtest result is about the same code that trades.

core-service now keeps 90 days of 1-minute candles.

This release also fixes two bugs found during the demo:
- Kafka never used its data volume, so recreating the container lost every topic.
- Days-old heartbeat signals in the outbox were published once Kafka recovered.

It is a feature, so the bump is major.

## Changes
- **Shared strategy package (`services/strategies-py`, `vajra_strategies`):**
  - `SmaCross(fast=20, slow=60).decide(closed, position)` is pure: no I/O, no clock and no logging. It holds long or flat with 1 contract.
  - It reads only the last `slow + 1` closed candles. When those candles span more than `slow + 5` minutes (a gap), it makes no decision.
- **`CoreClient` (`vajra_common`):**
  - Reads candles in 1-day windows, positions and instruments from the core-service REST API. Decimals are parsed as `Decimal`.
  - Every transport error, 5xx and invalid JSON raises `CoreUnavailable`.
- **core-service:**
  - Candle history is 90 days (was 7).
  - Each process start runs a one-time backward fill: newest window first, stopping when Delta returns nothing. A failure only logs a WARN, the forward sync still runs, and the fill retries on the next run.
- **signal-service:**
  - New `SmaCrossRunner`, ticking every 60 s:
    - It never decides on the newest stored candle, which can be a mid-minute snapshot.
    - It does nothing when the data is older than 4 minutes.
    - It sends at most one signal per candle, using `candle_time` plus a unique index.
    - It reads the position for the `TRADING_MODE` venue from core.
  - `STRATEGY` (`sma_cross` | `heartbeat` | `none`) is now the only switch, and the default is `sma_cross`. Other new settings: `SMA_FAST`, `SMA_SLOW`, `SMA_SYMBOL`, `SMA_SIZE`, `SMA_INTERVAL_SECONDS` and `CORE_BASE_URL`.
- **research-service:**
  - New endpoints `POST /api/v1/backtests` and `GET /api/v1/backtests/{id}`.
  - A decision at candle i fills at candle i+1's open, with slippage against us (default 2 bps).
  - The fee is `fee_rate × size × contract_value × price`. It defaults to the instrument's taker fee.
  - A position still open at the end is closed at the last close.
  - The end of the range is clamped to the current minute, and a snapshot candle at the live edge is dropped.
  - Metrics: trades, gross/net P&L, fees, max drawdown, win rate and missing minutes, plus `funding_included=false`.
  - Bad input returns 422 (bad range, more than 180 days, naive datetime, bad parameters, unknown symbol, not enough candles). Core errors return 503.
- **Incident fixes (see knowledge 0029):**
  - Compose sets `KAFKA_LOG_DIRS: /var/lib/kafka/data`, so Kafka really uses the `kafkadata` volume.
  - One shared outbox routine for heartbeat and sma_cross checks each row's age against a fresh clock before every send. The age is taken from `candle_time`, or from `generated_at` when `candle_time` is not set. A row older than 4 minutes is marked `expired_at` with a WARN and never sent.
  - The producer `request_timeout_ms` is 10 s.
- **Compose:**
  - signal-service gets `STRATEGY`, `SMA_FAST`, `SMA_SLOW`, `SMA_SYMBOL` and `CORE_BASE_URL=http://core-service:8081`.
  - research-service gets `CORE_BASE_URL`.
- **Docs:**
  - knowledge `0028-sma-cross-strategy-and-backtester.md` and `0029-kafka-storage-and-stale-outbox-incident.md`
  - Hinglish notes `10-backtesting-and-learning/03-sma-cross-aur-backtest.md` and `07-kafka-and-events/04-purana-signal-mat-bhejo.md`
  - 0026's stale-signal item is marked `Superseded by: 0029`

## DB migrations
- **signal schema:** Alembic `0003_signal_candle_time`.
  - Adds the nullable columns `signal_log.candle_time` and `signal_log.expired_at`.
  - Adds the partial unique index `signal_log_candle_uidx` on `(strategy, symbol, candle_time)` where `candle_time` is not null.
- **research schema:** Alembic `0002_backtest`, with tables `research.backtest_run` and `research.backtest_trade`.
- **core schema:** none (Flyway is unchanged).

## Contract changes
- None to Protobuf or Kafka.
- New REST API on research-service: `/api/v1/backtests`.

## Breaking changes
- **signal-service trades by default.** `STRATEGY` defaults to `sma_cross`, so it now places SMA-cross signals on PAPER (or `DELTA_TESTNET` if that mode is set). It used to run heartbeat.
  - The stop switch is now **`STRATEGY=none`**. `HEARTBEAT_ENABLED` from 2.4.0 no longer exists and is ignored.
  - With `STRATEGY=sma_cross`, signal-service needs `CORE_BASE_URL`; compose sets it.
- **Kafka must be recreated once, and its topics re-created.** Until now Kafka kept its data in `/tmp` inside the container. Picking up `KAFKA_LOG_DIRS` recreates the container, which loses every topic one last time.
  - On every machine, including the VPS: `scripts/compose.sh up -d kafka`, then `scripts/compose.sh up kafka-init`.
  - From then on, the data survives a recreate (verified with `--force-recreate`).
- **Expired outbox rows are dropped.** A signal that could not be published within 4 minutes is never sent. That is intended: a late signal is worse than a lost one.
- **Initial backward fill at the first start:** about 60 Delta calls per symbol. This took about 30 s on the laptop.

## Known follow-ups
All are listed in knowledge doc 0028.
- **Top priority: a maximum signal age on the consumer side (core or risk).** A signal stuck in Kafka while core is down can still become an order.
- Live can skip a candle when the 60 s loops drift, and so miss a cross.
- The backtest fills about 1 candle earlier than live.
- Funding is not modelled. There is no walk-forward and no parameter search (Phase 6).
- Smaller items:
  - an edge case in the fetch window
  - an off-by-one at the live edge of the backtest
  - runner DB calls run on the event loop
  - the backward fill is unpaced

## Rollback notes
- **Quick:** set `STRATEGY=none` and recreate signal-service.
- **Full:** redeploy the 2.5.0 images and compose. The new columns and tables are additive, so old code ignores them.
  - Alembic downgrades exist: signal `0003 → 0002` and research `0002 → 0001`.
  - Keep `KAFKA_LOG_DIRS` even when rolling back, otherwise topics are lost again on the next recreate.
