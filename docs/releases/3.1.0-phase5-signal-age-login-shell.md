# Phase 5 slices 0 and 1: stale-signal guard, gateway login and terminal shell

## Summary
- **Stale signals:** core-service now rejects any signal older than 5 minutes. A stale signal never trades, and each rejection is kept as an auditable order.
- **Login:** gateway-bff now has a single-user login with a session cookie, CSRF protection, a lockout and an audit table.
- **Terminal:** a new `ui` container (Nginx serving the Angular shell) is published only on `127.0.0.1:8088`. On the VPS, Tailscale exposes it privately, with no public port.

This is an enhancement, so the version bump is minor.

## Changes
- **core-service (slice 0):**
  - `vajra.signals.max-age` (default `PT5M`, must be positive).
  - **Stale signal:** an older signal becomes a `RISK_REJECTED` order with reason `STALE_SIGNAL`, with no risk call and no venue call.
    - It goes through the same idempotent create as `place` (`OrderService.createOnce`).
    - The usual `order.updated` audit and outbox entries are written.
  - **Invalid timing:** a missing `generated_at`, or one more than 30 s in the future, is invalid.
  - **Stale redelivery of an existing order:** logged as "already placed", or as "stuck" if the order is stuck.
- **gateway-bff (slice 1):**
  - **Endpoints:** Spring Security with a JSON login:
    - `GET /api/v1/auth/csrf`
    - `POST /api/v1/auth/login`
    - `POST /api/v1/auth/logout`
    - `GET /api/v1/session` returns `{username, tradingMode}`.
  - **Credentials:** one user, from `GATEWAY_ADMIN_USERNAME` and `GATEWAY_ADMIN_PASSWORD_HASH` (bcrypt, cost 12). The gateway refuses to start without them.
  - **Session cookie `VAJRA_SESSION`:**
    - HttpOnly, SameSite=Strict, and Secure set by `GATEWAY_COOKIE_SECURE` (default true; the laptop dev overlay sets false).
    - 30 min idle and 8 h absolute timeouts.
    - The session id changes on login, and no session exists before login.
  - **CSRF:** `csrf.spa()` with a cookie repository (`XSRF-TOKEN` / `X-XSRF-TOKEN`). It is required on every POST, including login, and the token is rotated on login.
  - **Lockout:** global. 5 failures within 15 min lock login for 15 min. Attempts are serialized, and a locked login returns 429 with `Retry-After`.
  - **Audit:** `gateway.audit_event` records `LOGIN_OK` (written before the session is created), `LOGIN_FAILED` (username sanitized, never the password), `LOGIN_LOCKED` and `LOGOUT`.
  - **Public paths:** only health, csrf and login. Everything else returns 401 JSON.
  - **Hash helper:** `scripts/gateway-password-hash.sh`.
- **ui (new):**
  - **Container:** Angular 22.2.x (strict TS and strict templates) built in `node:26.13.1-alpine` and served by `nginx:1.29.8-alpine`. It runs non-root on 8080 with `read_only`, `cap_drop: ALL`, `no-new-privileges`, 32 MB and 1 worker.
  - **Proxy:** only `^~ /api/` (gzip off) and `= /ws`.
  - **Headers:** CSP `default-src 'self'` with no inline script, `frame-ancestors 'none'`, `no-referrer`, `nosniff`, `X-Frame-Options: DENY` and Permissions-Policy.
  - **Caching:** `index.html` is `no-store`, hashed assets are immutable, and a missing js/css file gets a 404.
  - **Shell:**
    - Login page: CSRF is fetched before each attempt, autofill-safe, and shows the lockout in minutes.
    - Top bar:
      - mode badge: PAPER / TESTNET; any unknown mode is shown raw in red
      - connection dot: 15 s poll with a 5 s timeout
      - P&L placeholder
      - kill-switch marked disabled until slice 4
      - theme toggle and logout
    - Layout: a grid on desktop, toggle tabs on phones.
- **Infra and CI:**
  - The `ui` service is added to compose.
  - gateway-bff gets the auth env and `TRADING_MODE`.
  - The new `scripts/compose-vps.sh` uses base compose only, with no dev overlay.
  - `scripts/check-compose-ports.sh` runs in CI: base compose may publish only `ui` on `127.0.0.1:8088`.
  - The CI ui job runs test and build, plus `check-no-inline-script.mjs`.
  - `check-memory.sh` now includes `ui`.
- **Docs:**
  - knowledge `0030-terminal-access-login-and-signal-age.md`, which includes the Tailscale and VPS runbook
  - Hinglish notes `13-frontend-angular/02-login-aur-shell.md` and `12-devops-basics/04-tailscale-se-terminal.md`
  - 0028's consumer-side signal-age follow-up marked `Superseded by: 0030`

## Breaking changes
- **gateway-bff will not start without `GATEWAY_ADMIN_USERNAME` and `GATEWAY_ADMIN_PASSWORD_HASH`.** Set both before recreating it on every machine:
  1. Run `scripts/gateway-password-hash.sh`.
  2. Put the hash in the git-ignored `.env` **in single quotes**, because the hash contains `$`.
  3. Make sure `.env` ends with a newline before appending.

  Without these, gateway-bff crash-loops and `ui` never starts.
- **On the VPS, use `scripts/compose-vps.sh`, never `scripts/compose.sh`.** The dev overlay makes cookies non-Secure and publishes the gateway port.
- **The terminal is reachable on the VPS only after Tailscale is set up on the host** (runbook in 0030, done by Pranshu): `tailscale up` and `tailscale serve --bg --https=443 http://127.0.0.1:8088`.
- **Switching `TRADING_MODE`:** recreate gateway-bff together with core-service, so that the mode badge matches.

## Known follow-ups
All are listed in knowledge doc 0030.
- **Idle timeout:** an open tab polls, so in practice the session lasts until the 8 h absolute limit.
- **Global lockout:** any tailnet device could lock the user out.
- **Mode badge source:** it reads the gateway's own `TRADING_MODE`; slice 2 should take the mode from core.
- **Minor:**
  - the login lock has no wait timeout
  - `/ws` → `^~ /ws/` if sub-paths are added
  - logout shows "offline" on a 401
  - guestGuard can block `/login` for up to 5 s
  - a stale signal for an unknown symbol is not recorded

## Rollback notes
- **Quick:** stop the `ui` service. core-service and gateway-bff keep running, and nothing else depends on ui.
- **Full:** redeploy the 3.0.0 images and compose.
  - The `gateway.audit_event` table is additive and ignored by old code. Flyway has no down migration; drop the table by hand only if it is really needed.
  - The core signal-age check has no schema change.
