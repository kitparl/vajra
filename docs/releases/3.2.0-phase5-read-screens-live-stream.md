# Phase 5 slice 2: read screens and live stream

## Summary
The terminal now shows the market, orders, fills, positions, P&L and the halted state live, on phone and laptop.
- gateway-bff forwards read-only REST calls behind the login session.
- One WebSocket (`/ws`) pushes quotes, order, fill and position events from Kafka, plus risk state.
- This slice is read-only: no order placement and no kill-switch actions.

This is an enhancement, so the bump is minor.

## Changes
- **core-service:**
  - `GET /api/v1/quotes` returns every trading-enabled symbol as `{symbol, bestBid, bestAsk, markPrice, venueTime, receivedAt, stale}`, with decimals as strings and the stale rule at 10 s.
  - `GET /api/v1/status` returns `{tradingMode}`.
  - `QuoteCache.MAX_AGE` and `QuoteCache.isStale` are now the single source of the stale rule.
- **risk-service:**
  - `GET /api/v1/limits` and `GET /api/v1/rejections?limit=1..200` (default 50; out of range gives 400).
  - Both are behind `RISK_API_TOKEN` and are read-only.
- **gateway-bff, REST:** GET only, and every endpoint needs a session.
  - `/api/v1/instruments` (only trading-enabled)
  - `/api/v1/quotes`
  - `/api/v1/positions`
  - `/api/v1/pnl`
  - `/api/v1/orders` and `/api/v1/orders/{id}`
  - `/api/v1/candles`
  - `/api/v1/risk/status`, `/api/v1/risk/limits` and `/api/v1/risk/rejections`
- **gateway-bff, upstream errors:**
  - The gateway returns 503 `{"error":"UPSTREAM_UNAVAILABLE","upstream":"core"|"risk"}` when:
    - core or risk is down or times out
    - the upstream answers 5xx, 401 or 403
    - the upstream sends an empty body
  - Every other 4xx passes through unchanged.
  - Timeouts are 1 s to connect and 3 s to read.
- **gateway-bff, trading mode:** `/api/v1/session` now takes the mode from core `/status`. When core is unreachable it reports `"UNKNOWN"`, and the badge shows it in red. The gateway's own `TRADING_MODE` is removed.
- **gateway-bff, WebSocket `/ws`:**
  - **Handshake:** needs a session (otherwise 401) and an `Origin` exactly equal to `GATEWAY_UI_ORIGIN` (otherwise 403).
  - **Messages:** `{type, data}`, where type is `hello`, `quote`, `order`, `fill`, `position`, `risk` or `upstream`.
  - **Kafka:** consumer group `gateway-bff` reads `order.updated`, `fill.created` and `position.updated`, with decimals kept as strings. A malformed record is skipped. If Kafka is down at startup, the gateway still starts and REST keeps working.
  - **Pollers:** quotes every 1 s and risk every 2 s, only while a socket is open. Risk is sent when it changes and re-sent every 10 s. Every failed poll broadcasts `upstream ... available:false`.
  - **Slow clients:** each send runs on its own virtual thread, behind a 5 s / 256 KiB decorator. A stalled phone is closed and does not block the others.
  - **Session end:** sockets are bound to a stable session key, so a login id rotation does not unbind them. When the session ends (logout, timeout or the 8 h limit), its sockets close with code 4401. This includes sockets still waiting for their first message.
- **ui (Angular):**
  - **Live data service:**
    - It takes a REST snapshot, then opens the WebSocket.
    - On a dropped connection it reconnects after 1, 2, 5, then every 10 s.
    - The snapshot is re-taken on every socket open.
    - A socket silent for 10 s is closed and reconnected.
    - Close code 4401 sends you to the login page.
  - **Watchlist:**
    - mark, bid and ask
    - 24 h change with ▲/▼
    - a 600 ms flash when a value changes
    - a "stale" marker, also shown while core is down
  - **Orders:** a list plus a detail view with fills and transitions.
  - **Positions:** every value is shown exactly as core sends it.
  - **Top bar:**
    - real net P&L, refreshed at most every 2 s on quote and position messages
    - a "HALTED" text badge
    - the mode badge, taken from the session
  - **Errors:** a "core unavailable" or "risk unavailable" notice appears only in the panel that failed.
  - **Money:** the UI computes no money values. The 24 h change % is the only number it calculates, for display only.
- **Infra:**
  - gateway-bff gets `CORE_BASE_URL`, `RISK_BASE_URL`, `RISK_API_TOKEN`, `KAFKA_BOOTSTRAP` and `GATEWAY_UI_ORIGIN` (default `http://localhost:8088`). `TRADING_MODE` is removed.
  - `.env.example` gets `GATEWAY_UI_ORIGIN=`.
  - No new published ports.
- **Docs:**
  - knowledge `0031-read-screens-and-live-stream.md`
  - Hinglish notes `13-frontend-angular/03-live-data-aur-websocket.md` and `07-kafka-and-events/05-gateway-bhi-sunta-hai.md`
  - two 0030 lines marked `Superseded by: 0031`

## DB migrations
- None. risk-service reads its existing `risk_limit` and `risk_decision` tables. No schema change in any service.

## Contract changes
- No Protobuf or Kafka contract changes. gateway-bff is a new consumer of existing topics (group `gateway-bff`).
- **New REST:**
  - core `/api/v1/quotes` and `/api/v1/status`
  - risk `/api/v1/limits` and `/api/v1/rejections`
  - the gateway read endpoints listed above
- **New WebSocket contract:** `/ws`, as described above.

## Breaking changes
- **`RISK_API_TOKEN` must be set for gateway-bff.** If it is blank, gateway-bff refuses to start. Compose already passes it from `.env`.
- **On the VPS, set `GATEWAY_UI_ORIGIN` before deploying.** Use the exact Tailscale URL in `.env`, for example `GATEWAY_UI_ORIGIN=https://<vps-name>.<tailnet>.ts.net`, with no trailing slash. Without it, the localhost default makes every WebSocket get 403 and the terminal stays on "reconnecting". An origin with a trailing slash or a path stops gateway-bff at startup.
- **Switching `TRADING_MODE` now needs only a core-service recreate.** The badge reads core's mode, and gateway-bff no longer has `TRADING_MODE`.

## Known follow-ups
All of these are listed in knowledge doc 0031.
- **Rejections index:** the rejections query has no index. Add a V3 partial index before live trading.
- **Pending window:** an order event in the brief window before a new socket is ready can be missed until the next event or a reconnect.
- **Core 4xx in a poll:** this broadcasts nothing, so the watchdog keeps reconnecting.
- **Session lifetime:** an open tab stays logged in until the 8 h absolute limit.
- **Kafka backlog:** after a gateway outage, the backlog is replayed to connected sockets. This is display only.
- **Minor:**
  - a dev-mode NG0956 warning from the watchlist flash
  - the 24 h reference assumes 1-minute candles
  - a WARN on every poll when the token is wrong

## Rollback notes
- **Quick:** redeploy the 3.1.0 images for gateway-bff and ui. core-service and risk-service only gained read endpoints, which old callers ignore.
- **Full:** redeploy the 3.1.0 images and compose.
  - There is nothing to roll back in the database.
  - The 3.1.0 gateway needs `TRADING_MODE` again (compose 3.1.0 sets it).
  - The `gateway-bff` Kafka consumer group can be left as is, or deleted with `kafka-consumer-groups --delete --group gateway-bff`.
